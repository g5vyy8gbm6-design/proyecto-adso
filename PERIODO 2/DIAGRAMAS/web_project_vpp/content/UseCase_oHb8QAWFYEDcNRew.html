AUTENTICACION Y PERFILES : System

Use Case - INICIAR SESION link

Properties
Name Value
Description

El sistema permite a un usuario previamente registrado acceder a la plataforma web mediante el ingreso de sus credenciales de acceso: correo electrónico y contraseña.  

el sistema valida las credenciales contra la base de datos      . Si la información es correcta, genera una sesión activa y redirige al usuario al panel de control correspondiente a su rol      . En caso de credenciales incorrectas o cuenta inactiva/suspendida, el sistema bloquea el acceso y muestra un mensaje informativo      .

SUPERADMINISTRADOR
■ Workflow // FLUJO DE TRABAJO
    • Accede al formulario de login desde una ruta administrativa segura.
    • Ingresa sus credenciales maestras (correo electrónico de superadministrador y contraseña).
    • El sistema valida el hash de la clave, verifica permisos de nivel raíz y redirige al panel global de administración.
■ Business Logic // LOGICA DE NEGOCIO
    • Las contraseñas se cotejan cifradas y el sistema valida que el rol corresponda a Superadministrador.
    • Si falla la autenticación, se registra un evento en los logs (registros) del servidor para prevenir ataques de fuerza bruta y se notificara de forma urgente a un superadministrador de nivel superior o autenticados.
    •
■ Decisions // DECISIONES
    • Se decide implementar la expiración automática de la sesión por inactividad prolongada por tratarse de acceso con privilegios elevados.
    • Se limita la visualización de mensajes de error a un texto genérico ("Credenciales inválidas") para no revelar si el correo existe en la base de datos.

ESTABLECIMIENTO (DUEÑO)
■ Workflow // FLUJO DE TRABAJO
    • Ingresa a la opción de inicio de sesión de la aplicación web.
    • Introduce el correo electrónico registrado como propietario y la contraseña correspondiente
    • Al autenticarse con éxito, el sistema verifica el estado de su establecimiento y suscripción, redirigiéndolo al panel de administración del local.
■ Business Logic // LOGICA DE NEGOCIO
    • La autenticación permite el acceso si la cuenta de usuario está activa.
    • Si el establecimiento o la suscripción se encuentran inactivos o vencidos, el sistema le permite ingresar pero restringe ciertas funciones operativas e informa sobre la renovación de plan.
    • Se asignan variables de sesión con los identificadores del negocio asociado.
■ Decisions // DECISIONES
    • Se permite al dueño mantenerse autenticado en múltiples dispositivos simultáneamente para facilitar la gestión del negocio.

PERSONAL/PROFESIONAL
■ Workflow // FLUJO DE TRABAJO
    • Ingresa sus credenciales corporativas o personales creadas previamente por el Dueño del local.
    • Inicia sesión y el sistema valida su vinculación activa con un establecimiento registrado.
■ Business Logic // LOGICA DE NEGOCIO
    • Es redirigido automáticamente a su vista de agenda de citas asignadas para el día.
    • El sistema valida que el empleado tenga un estado Activo tanto en su usuario como en la relación con el establecimiento.
    • Si el local o el empleado han sido desactivados, se deniega la autenticación notificando al usuario que contacte al administrador de su establecimiento
■ Decisions // DECISIONES
    • Se limita el panel de inicio del profesional exclusivamente a la gestión de sus citas y estado de atención para simplificar la interfaz operativa

CLIENTE
■ Workflow // FLUJO DE TRABAJO
    • Accede al formulario de login desde el menú principal o al intentar realizar una reserva de cita.
    • Ingresa su correo electrónico y contraseña registrados.
    • El sistema autentica la cuenta, valida si posee sanciones activas y redirige al mapa/búsqueda de locales o de vuelta a la reserva pendiente.
■ Business Logic // LOGICA DE NEGOCIO
    • La clave ingresada se valida con el cifrado guardado en la base de datos
    • Si el usuario tiene una sanción activa por cancelaciones repetitivas, puede iniciar sesión normalmente, pero las acciones de reserva quedarán restringidas de acuerdo a las reglas del sistema.
■ Decisions // DECISIONES
    • En caso de que el inicio de sesión sea interrumpido por un intento fallido, se mostrará el enlace directo a "Recuperación de Contraseña"
    • Se almacena el token de sesión en el navegador para mantener el acceso activo durante las búsquedas y reservas

login
Steps
1. El Superadministrador ingresa a la ruta privada de acceso administrativo de la plataforma.
2. Introduce su correo maestro y contraseña en el formulario de inicio de sesión.
3. El sistema valida las credenciales contra la base de datos global.
4. El sistema evalúa el resultado de la autenticación:
5. if las credenciales Incorrectas
    5.1. El sistema notifica "Credenciales de administración inválidas"
    5.2. registra el intento de acceso en la bitácora de seguridad.
6. else if El sistema evalúa el estado de la cuenta en la base de datos:
    6.1. if la cuenta cuenta con autenticación de dos factores activa: El sistema solicita el código de verificación dinámico.
        6.1.1. if el código de verificación es Incorrecto o Expirado: El sistema deniega el acceso y solicita un nuevo código.
        6.1.2. else if El sistema genera el token de sesión con rol de Superadministrador y despliega el panel de control global.
               end if
         end if
   end if
