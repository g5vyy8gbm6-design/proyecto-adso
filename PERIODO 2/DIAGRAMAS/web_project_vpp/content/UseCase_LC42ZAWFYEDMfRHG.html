Description

El sistema permite al Superadministrador (para pagos de suscripción) o al Dueño de Establecimiento (para abonos directos) cambiar el estado de una transacción financiera.

 

Permite transicionar un pago de estado Pendiente de Verificación a Aprobado o Rechazado, actualizando automáticamente el estado de la suscripción o de la cita asociada.

FLUJO DE ESTADO DE PAGOS
■ Workflow //FLUJO DE TRABAJO
    • Accede al módulo de "Verificación de Pagos Manuales".
    • Revisa el listado de transferencias bancarias pendientes enviadas por los Dueños de Establecimientos.
    • Compara la referencia y el comprobante cargado.
    • Cambia el estado a "Aprobado" o "Rechazado".
    • Si aprueba, el sistema renueva la suscripción y emite la notificación.
■ Business Logic //LOGICA DE NEGOCIO
    • Aprobar un pago de suscripción cambia automáticamente el estado del negocio a Activo. Rechazar el pago mantiene la suscripción suspendida o en mora.
    • Todo cambio manual de estado debe registrar obligatoriamente: fecha, hora, usuario administrativo que ejecutó la acción y un campo de nota o motivo (especialmente si es rechazado).
    • No se permite revertir a estado Pendiente un pago que ya ha sido marcado como Aprobado.
■ Decisions //DECISIONES
    • Si un pago es marcado como "Rechazado", el sistema solicitará obligatoriamente seleccionar o escribir la razón (ej. "Comprobante no legible", "Monto incompleto", "Referencia inexistente") para que sea enviada en la notificación automática al cliente o propietario.

(VERIFICACIÓN Y APROBACIÓN MANUAL DE PAGOS)
Steps
1. El Superadministrador ingresa a la consola central y navega a "Gestión Financiera" => "Verificación de Pagos Pendientes".
2. El sistema recupera la lista de transacciones en estado Pendiente de Verificación registradas por los dueños de establecimientos.
3. Selecciona una transacción específica para revisar la información ingresada (Monto, Número de referencia, Fecha y Comprobante adjunto).
4. Tras verificar el abono en la cuenta bancaria del sistema, el Superadministrador selecciona la opción "Aprobar Pago".
5. El sistema evalúa la confirmación de aprobación:
    5.1. if el pago es aprobado con éxito:
        5.1.1. El sistema cambia el estado del pago a Aprobado en el historial
        5.1.2. El sistema extiende/renueva automáticamente la vigencia de la suscripción del establecimiento
        5.1.3. El sistema verifica si el establecimiento se encontraba en estado Inactivo/Suspendido por Mora
            5.1.3.1. if el negocio estaba suspendido por falta de pago:
                5.1.3.1.1. El sistema cambia el estado de la suscripción a Activa y restablece la visibilidad pública del local
            5.1.3.2. else if El sistema mantiene el negocio en estado Activo actualizando sus fechas límite.
                5.1.3.2.1. El sistema despacha el comprobante/factura digital y la notificación de pago aprobado al correo del propietario
                     end if
         end if

(RECHAZO DE PAGOS POR INCONCONSISTENCIAS)
Steps
1. El Superadministrador revisa una transacción pendiente en el módulo de verificación y detecta inconsistencias (ej. comprobante ilegible, monto insuficiente, referencia no encontrada en extractos bancarios).
2. Selecciona la opción "Rechazar Pago".
3. El sistema despliega un campo obligatorio para registrar el motivo detallado del rechazo.
4. El Superadministrador ingresa la justificación y confirma la acción.
5. El sistema evalúa el registro del motivo de rechazo:
    5.1. if el campo de motivo o justificación está vacío:
        5.1.1. El sistema frena el rechazo y exige "Debe ingresar una explicación clara para notificar al establecimiento sobre el motivo del rechazo".
    5.2. else if El sistema cambia el estado de la transacción a Rechazado en la bitácora financiera
        5.2.1. El sistema evalúa el estado actual de la suscripción del negocio:
            5.2.1.1. if la suscripción del negocio ya se encuentra vencida:
                5.2.1.1.1. El sistema restringe las operaciones del negocio o lo mantiene en Período de Gracia / Suspendido
            5.2.1.2. else if El sistema mantiene el estado actual de la suscripción hasta la llegada de la fecha límite original de vencimiento.
                5.2.1.2.1. El sistema despacha una notificación de alerta urgente al propietario indicando el rechazo del pago y la justificación para que proceda a cargar un nuevo comprobante
                     end if
         end if
