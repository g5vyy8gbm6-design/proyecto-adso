Description

El sistema permite al Superadministrador modificar el estado operativo de la suscripción de un establecimiento (ej. pasar de Activa a Suspendida, Cancelada o Inactiva por Mora, cambio de plan de suscripcion).

CAMBIO DE ESTADO DE PLANES
■ Workflow //FLUJO DE TRABAJO
    • El Superadministrador accede al panel global y busca el establecimiento en el directorio de "ESTABLECIMIENTOS REGISTRADOS".
    • Selecciona el negocio y presiona la opción "Gestionar Suscripción / Cambiar Estado".
    • Elige el nuevo estado de la cuenta (ej. Suspendida por No Pago, Cancelada, Activa / Reactivada).
    • Ingresa el motivo administrativo del cambio de estado.
    • Presiona "Confirmar Cambio de Estado".
    • El sistema actualiza los registros, ajusta los accesos a la plataforma y notifica por correo electrónico al propietario del establecimiento.
■ Business Logic //LOGICA DE NEGOCIO
    • Deshabilita el inicio de sesión para el Dueño y su Personal, frena el motor de agendamiento y oculta las sedes del motor de búsqueda pública .
    • Los datos históricos del local (clientes, citas previas, estadísticas) no se eliminan; quedan en pausa hasta una eventual reactivación.
    • Al cambiar el estado de nuevo a Activa, el sistema restituye automáticamente la visibilidad del negocio y habilita las credenciales del personaL.
    • Todo cambio de estado realizado por el Superadministrador debe ser auditado, registrando fecha, hora, usuario ejecutante y la justificación.
■ Decisions //DECISIONES
    • Si un establecimiento es suspendido mientras posee citas agendadas a futuro, el sistema congelará la agenda y notificará a los clientes afectados para que gestionen la cancelación o reasignación de sus reservas.

(MODIFICACIÓN MANUAL DE ESTADO DE SUSCRIPCIÓN)
Steps
1. El Superadministrador ingresa a la consola global y navega a "Gestión de Suscripciones" => "Ver Suscripciones de Establecimientos".
2. elecciona la sede deseada y presiona la opción "Cambiar Estado de Suscripción".
3. El sistema despliega los estados disponibles (Activa, Pendiente de Pago, Suspendida, Cancelada) y solicita la justificación administrativa.
4. El Superadministrador confirma el cambio.
5. El sistema evalúa el nuevo estado asignado:
    5.1. if el estado seleccionado es Suspendida o Cancelada:
        5.1.1. El sistema cambia la condición de la suscripción y desencadena la inhabilitación del perfil público del establecimiento.
        5.1.2. El sistema bloquea el agendamiento de nuevas citas por parte de los clientes
        5.1.3. El sistema despacha la notificación administrativa al propietario explicando el cambio de estado de su cuenta
    5.2. else if (Estado seleccionado es Activa):
        5.2.1. El sistema evalúa si el pago asociado está validado o aprobado
            5.2.1.1. if el pago no se encuentra verificado ni aprobado:
                5.2.1.1.1. El sistema emite la alerta "No se puede activar la suscripción sin la aprobación previa del pago correspondiente".
            5.2.1.2. else if
                5.2.1.2.1. El sistema restablece la suscripción a estado Activa, actualiza la fecha límite de cobertura y habilita las operaciones normales de la sede
                     end if
         end if

(CAMBIO AUTOMÁTICO DE ESTADO POR VENCIMIENTO)
Steps
1. El Sistema ejecuta la rutina de verificación nocturna de vigencia de suscripciones.
2. Compara la fecha actual contra la fecha límite de vencimiento de cada suscripción en la base de datos.
3. El sistema evalúa el tiempo restante o el sobrepaso de la fecha de cobro:
    3.1. if la suscripción venció el día de hoy Y no registra un pago en proceso de validación
        3.1.1. El sistema cambia el estado de la suscripción a "En Período de Gracia" (o Pendiente de Pago por 3 días hábiles).
        3.1.2. El sistema envía una notificación automática de cobro urgente al correo del propietario
    3.2. else if
        3.2.1. if ha transcurrido el período de gracia sin la recepción o aprobación del pago:
            3.2.1.1. El sistema cambia automáticamente el estado de la suscripción a "Suspendida por Mora".
            3.2.1.2. El sistema inhabilita la visibilidad pública del negocio (RF26) y emite la notificación final de suspensión
        3.2.2. else if
            3.2.2.1. El sistema mantiene la suscripción en su estado actual.
               end if
         end if
