Use Case - APLICAR SANCIÓN AUTOMÁTICA POR CANCELACIONES link

Properties
Name Value
Description

El sistema aplica de forma autónoma una sanción operativa o financiera al cliente cuando incurre en una cancelación tardía (menos de 5 horas, RF39) o sobrepasa el límite mensual de anulaciones (RF40).

Dependiendo de la configuración del local, la sanción puede consistir en la pérdida no reembolsable del anticipo, el cobro de una tarifa de penalización en la siguiente reserva o la inhabilitación temporal de la cuenta.

SISTEMA
■ Workflow //FLUJO DE TRABAJO
    • Ejecuta una cancelación extemporánea ($< 5\text{ horas}$) o alcanza el límite mensual permitido de anulaciones.
    • El sistema procesa el evento y le notifica inmediatamente la penalización aplicada.
    • Si la sanción es de tipo financiero, el sistema retiene el anticipo abonado.
■ Business Logic //LOGICA DE NEGOCIO
    • Si la cita requería un abono previo (ej. 30% o 50%), el sistema ejecuta la retención automática sin generar orden de reembolso al monedero del cliente.
    • La inhabilitación por sanción automática bloquea el motor de agendamiento (RF09) para ese usuario en la sede durante el tiempo estipulado en la regla.
    • Cada sanción aplicada genera un ticket de penalización con marca de tiempo, cita asociada y causa explícita.
■ Decisions //DECISIONES
    • Si el cliente solicita el levantamiento de la sanción a través de soporte, el Dueño de Establecimiento puede autorizar el perdón de la penalización desde su panel, lo cual reembolsa el saldo a favor o devuelve el estado del usuario a "Activo".

(PROCESAMIENTO Y APLICACIÓN AUTOMÁTICA DE LA SANCIÓN)
Steps
1. El Sistema recibe el evento disparador desde el control de cancelaciones (<> RF40) al detectar que un usuario ha alcanzado o superado el límite permitido de cancelaciones en el mes.
2. El sistema consulta en la base de datos el historial del usuario para verificar el nivel de reincidencia (sanciones previas recibidas en el año).
3. El sistema evalúa el historial de sanciones del cliente para determinar el periodo de bloqueo:
    3.1. if el usuario es la primera vez que incurre en el exceso de cancelaciones en el año:
        3.1.1. El sistema asigna una Sanción Leve: inhabilita la creación de nuevas reservas por un periodo automático de 7 días continuos.
    3.2. else if (El usuario registra sanciones previas en los últimos 12 meses):
        3.2.1. if el usuario registra exactamente una sanción previa:
            3.2.1.1. El sistema asigna una Sanción Moderada: inhabilita la creación de nuevas reservas por un periodo automático de 15 días continuos.
        3.2.2. else if (El usuario registra dos o más sanciones previas):
            3.2.2.1. El sistema asigna una Sanción Grave: inhabilita la creación de nuevas reservas por un periodo de 30 días continuos y marca el perfil para revisión del Superadministrador.
               end if
         end if
4. El sistema registra en el expediente del cliente el tipo de sanción, la fecha de inicio, la fecha exacta de finalización y el estado de penalización (Activo).
5. El sistema activa el bloqueo en el motor de agendamiento para este usuario (Bloqueo Reservas por Sanción).
6. El sistema envía de forma inmediata una notificación automática al correo del cliente y push a la app detallando: el motivo del bloqueo, la duración de la sanción y la fecha en que podrá volver a reservar.

(LEVANTAMIENTO EXPIRATORIO AUTOMÁTICO DE LA SANCIÓN)
Steps
1. El Sistema ejecuta una rutina periódica programada de verificación de sanciones temporales.
2. Compara la fecha y hora actual del servidor contra la fecha de finalización de la sanción de cada cliente en la base de datos.
3. El sistema evalúa el cumplimiento del tiempo de penalización:
    3.1. if la fecha actual es mayor o igual a la fecha de finalización de la sanción:
        3.1.1. El sistema cambia el estado de la sanción a Expirada.
        3.1.2. El sistema remueve el bloqueo de agendamiento, devolviendo al cliente el acceso para reservar citas normalmente.
        3.1.3. El sistema envía una notificación al cliente informando que su cuenta ha sido reactivada y el servicio de reservas está disponible nuevamente
    3.2. else if El sistema mantiene la restricción activa y frena cualquier intento de agendamiento
         end if
