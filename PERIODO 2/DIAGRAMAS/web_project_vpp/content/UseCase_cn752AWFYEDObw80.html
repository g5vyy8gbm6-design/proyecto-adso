HISTORIAL DE PAGOS DE SUSCRIPCION
■ Workflow //FLUJO DE TRABAJO
    • Accede al módulo "Planes y Pagos" y selecciona el plan deseado.
    • Selecciona el método de pago (pasarela en línea o transferencia bancaria manual).
    • Si elige pasarela, completa los datos de pago y ejecuta la transacción.
    • Si elige transferencia manual, adjunta el comprobante digital (imagen/PDF) e ingresa el número de referencia.
    • Presiona "Enviar / Registrar Pago".
    • El sistema procesa la solicitud, genera un recibo de pago preliminar y notifica la transacción.
■ Business Logic //LOGICA DE NEGOCIO
    • Los pagos procesados por pasarela automática cambian inmediatamente el estado de la suscripción a "Activa".
    • Los pagos registrados mediante transferencia manual requieren la aprobación previa del Superadministrador (RF38) antes de habilitar el servicio.
    • Todo registro de pago debe almacenar de forma obligatoria: monto, fecha, hora, método de pago, referencia transaccional e identificador del establecimiento.
■ Decisions //DECISIONES
    • Si la transacción es rechazada por la pasarela de pagos, el sistema muestra el error devuelto por la entidad financiera y permite al usuario reintentar con otro método.

REGISTRO DE PAGOS DE SUSCRIPCION
Steps
1. El Dueño de Establecimiento ingresa a su panel de administración y navega a "Mi Suscripción" => "Registrar Pago de Suscripción" (tras seleccionar o renovar su plan
2. El sistema recupera el valor a pagar, la fecha límite de vencimiento de la suscripción y los métodos de pago habilitados (Transferencia Bancaria / Pasarela Directa).
3. El propietario adjunta el número de comprobante/referencia, la fecha de la transacción y carga la foto/PDF del recibo de pago.
4. Presiona el botón "Enviar Comprobante de Pago".
5. El sistema evalúa la validez de los datos y el archivo adjunto:
    5.1. if el archivo excede el tamaño máximo permitido (ej. mayor a 5 MB), presenta un formato no soportado O el número de referencia está vacío:
        5.1.1. El sistema frena el envío y notifica "El comprobante adjunto no es válido o la referencia de pago está incompleta".
    5.2. else if El sistema guarda el registro de la transacción en la base de datos marcándola en estado "Pendiente de Verificación".
        5.2.1. El sistema genera la alerta automática para el equipo administrativo y envía la notificación de recibido al correo del propietario
         end if
