SISTEMA
■ Workflow //FLUJO DE TRABAJO
    • Detecta un evento gatillo en el sistema (ej. confirmación, edición, cancelación o recordatorio programado de cita).
    • Compila la plantilla de mensaje correspondiente integrando los datos dinámicos (nombre del cliente, fecha, hora, local, servicio).
    • Envía el aviso por el canal preferido del usuario (correo electrónico / push).
    • Registra la trazabilidad y el estado de entrega de la notificación en la base de datos.
■ Business Logic //LOGICA DE NEGOCIO
    • Es un caso de uso con relación de inclusión (<<include>>) u oyente de eventos proveniente de la gestión de citas.
    • Los recordatorios previos a la cita se programan automáticamente con un tiempo de antelación configurable (ej. 24 horas o 5 horas antes).
    • Si el envío por un canal falla, el sistema intenta un reintento automático o cambia al canal secundario registrado.
■ Decisions //DECISIONES
    • Los usuarios pueden personalizar en su perfil los tipos de notificaciones que desean recibir, exceptuando las alertas críticas de seguridad o cancelaciones.

DESPACHO DE EVENTOS DE CITAS Y RESERVAS
Steps
1. El Sistema detecta la ejecución de un evento disparador en el flujo de citas (Reserva, Modificación o Cancelación).
2. El sistema recupera la plantilla de notificación correspondiente al evento y extrae los datos del cliente, barbero, sede, fecha y hora.
3. El sistema evalúa el canal de comunicación predeterminado y los datos de contacto registrados del destinatario:
    3.1. if el número de teléfono celular o el correo electrónico del destinatario son inválidos o no existen en la base de datos: El sistema registra el fallo de envío en la bitácora de notificaciones y marca el evento como "No Entregado por Datos Incompletos".
    3.2. else if
        3.2.1. El sistema despacha el mensaje a través del Sistema de Notificaciones (NotifService) (vía Correo Electrónico / WhatsApp / Push Notification).
        3.2.2. El sistema evalúa la respuesta del servidor del servicio de notificaciones:
            3.2.2.1. if el servicio externo reporta un error de entrega (ej. rebote o servidor caído): El sistema programa hasta 3 reintentos automáticos en intervalos progresivos y deja el registro en estado "Pendiente de Reintento".
            3.2.2.2. else if (Despacho Exitoso): El sistema confirma la entrega en la base de datos con estado "Enviado".
                     end if
         end if

(RECORDATORIOS AUTOMÁTICOS PREVIOS A LA CITA)
Steps
1. El Sistema ejecuta una tarea programada en segundo plano (Cron Job) a intervalos regulares para buscar citas próximas a atenderse (ej. 24 horas y 2 horas antes de la cita).
2. El sistema recupera el listado de citas confirmadas que coinciden con la ventana de tiempo del recordatorio.
3. El sistema evalúa el estado de las citas en la base de datos:
    3.1. if la cita se encuentra en estado Cancelada, Inasistencia o Finalizada: El sistema omite el registro y no genera la notificación.
    3.2. else if (Cita en estado Confirmada):
        3.2.1. El sistema construye el mensaje personalizado con el enlace de confirmación o cancelación anticipada (RF39/RF40) y solicita al NotifService la emisión inmediata de la alerta al cliente y al barbero.
         end if

(ALERTAS DE SUSCRIPCIÓN Y SANCIONES)
Steps
1. El Sistema detecta una modificación de estado de cuenta en los módulos disciplinarios o administrativos (Sanción por Cancelaciones, Bloqueo o Cambio de Estado de Suscripción del Negocio).
2. El sistema identifica el rol del destinatario (Cliente, Personal o Dueño de Establecimiento).
3. El sistema evalúa la gravedad de la alerta:
    3.1. if la notificación corresponde a una Sanción o Suspensión de Servicio: El sistema despacha una notificación de alta prioridad vía correo electrónico y alerta Push en la aplicación explicando el motivo, la duración de la medida y los canales de apelación o pago.
    3.2. else if (Notificación Informativa / Recordatorio de Pago): El sistema envía un mensaje estándar al panel del usuario y correo de contacto registrado.
         end if
