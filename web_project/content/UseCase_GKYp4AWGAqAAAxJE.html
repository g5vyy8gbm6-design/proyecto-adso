PANEL DE RESERVAS : System

Use Case - AGENDAR RESERVA link

Name Value
Description

 

El sistema permite al cliente seleccionar un servicio, fecha, horario y profesional disponible para registrar una cita formal en la plataforma.

El proceso valida la ausencia de sanciones o bloqueos previos en la cuenta del cliente, reserva la franja horaria en la agenda del establecimiento y envía notificaciones automáticas de confirmación a ambas partes.

CLIENTE
■ Workflow //FLUJO DE TRABAJO
    • Selecciona el servicio y la franja horaria disponible deseada en la vista de disponibilidad.
    • Revisa el resumen del agendamiento (local, profesional, fecha, hora y valor).
    • Confirma los datos de contacto y la reserva.
    • El sistema procesa la solicitud, bloquea el turno en la agenda y emite el comprobante digital.
    • Se disparan las notificaciones automáticas de confirmación vía correo/push.
■ Business Logic //LOGICA DE NEGOCIOS
    • El sistema verifica las reglas de penalización: si el usuario registra sanciones o bloqueos por inasistencias o incumplimientos previos, se restringe la creación de nuevas reservas.
    • Una vez confirmada la cita, la franja de tiempo seleccionada se inactiva inmediatamente para otros usuarios.
    • Cada reserva genera un código único de seguimiento con estado inicial "Confirmada / Pendiente de Atención".
■ Decisions //DECISIONES
    • Si el cliente supera el límite permitido de cancelaciones tardías o ausencias (no-show), la cuenta queda inhabilitada temporalmente para el agendamiento directo.

CLIENTE
Steps
1. El Cliente selecciona la fecha, hora y barbero disponibles y presiona el botón "Confirmar Reserva".
2. El sistema ejecuta la verificación de sanciones en segundo plano
    2.1. if el perfil del cliente presenta una sanción activa o restricción de bloqueo por inasistencias/cancelaciones: El sistema interrumpe inmediatamente el proceso, deshabilita la reserva y despliega el mensaje "No es posible completar la reserva. Su cuenta cuenta con una restricción vigente hasta [Fecha]".
    2.2. else if El sistema evalúa si el servicio requiere abono/anticipo para su confirmación:
        2.2.1. if la sede exige un pago previo del anticipo: El sistema redirige a la pasarela de pagos y espera la confirmación del pago.
            2.2.1.1. if la transacción es Rechazada o se cancela la pasarela: El sistema cancela la reserva temporal, libera el horario en la agenda y muestra la alerta de pago fallido.
            2.2.1.2. else if (Pago Aprobado):El sistema registra la cita en estado "Confirmada", guarda los datos del pago en la base de datos y despacha la confirmación mediante el servicio de notificaciones
            2.2.1.3. else if (Sin anticipo requerido): El sistema crea la cita en estado "Confirmada" en la base de datos y activa el despacho de notificaciones automáticas
                     end if
               end if
         end if

Preconditions El cliente debe estar autenticado en la plataforma y contar con un estado de cuenta activo (sin penalizaciones pendientes). El servicio y horario seleccionados deben estar marcados como disponibles.
Post-conditions La cita queda registrada en estado "Confirmada", la agenda del profesional se actualiza en tiempo real y se emiten los recordatorios correspondientes.
