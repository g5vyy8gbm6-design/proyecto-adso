Description

El sistema permite modificar el estado de un empleado registrado en el establecimiento (ej. pasar de Activo a Inactivo / Suspendido / Vacaciones y viceversa).

 CAMBIAR ESTADO DE EMPLEADOS : Use Case

ESTABLECIMIENTO
■ Workflow //FLUJO DE TRABAJO
    • Ingresa al panel de administración y navega a la lista de "Empleados"
    • Selecciona al empleado objetivo y presiona la opción "Cambiar Estado" o utiliza el conmutador
    • Selecciona el motivo de la inhabilitación (ej. "Vacaciones", "Licencia médica", "Retiro definitivo").
    • Confirma el cambio de estado.
    • El sistema actualiza el registro, deshabilita la agenda del profesional y notifica el ajuste.
■ Business Logic //LOGICA DE NEGOCIO
    • Al inhabilitar a un empleado, el sistema valida si existen citas Confirmadas o Pendientes en su agenda futura.
    • Si existen citas asociadas al trabajador que se inactiva, el sistema exige reasignar dichas reservas a otro profesional del local o proceder con la cancelación notificando a los clientes
    • Un empleado en estado "Inactivo" pierde inmediatamente sus credenciales de acceso al panel de personal hasta que sea reactivado.
■ Decisions //DECISIONES
    • Si el propietario inactiva a un empleado por motivo de retiro definitivo, el cupo de personal liberado podrá ser utilizado para registrar un nuevo trabajador sin sobrepasar el límite del plan de suscripción

(INACTIVACIÓN / SUSPENSIÓN DE UN EMPLEADO)
Steps
1. El Dueño de Establecimiento ingresa a su panel de administración y navega a "Gestión de Personal" => "Lista de Empleados"
2. Selecciona un colaborador activo y presiona el botón o switch "Inactivar / Deshabilitar Empleado".
3. El sistema consulta la agenda asignada al colaborador.
4. El sistema evalúa el estado de las citas asociadas al barbero:
    4.1. if el colaborador tiene citas futuras en estado Confirmada o Pendiente en su agenda:
        4.1.1. El sistema bloquea la inactivación inmediata y despliega la alerta de gestión: "El colaborador tiene [N] citas agendadas pendientes. Debe reasignar las citas a otro profesional o cancelarlas antes de desactivar su perfil".
        4.1.2. if el propietario decide reasignar o cancelar las citas pendientes desde la alerta:
            4.1.2.1. El sistema procesa los cambios en la agenda, libera al barbero, envía las notificaciones a los clientes afectados (<<include>> RF14) y procede a inactivar la cuenta.
        4.1.3. else if
            4.1.3.1. El sistema cancela la operación y mantiene al empleado en estado Activo.
        4.1.4. else if (No existen citas pendientes agendadas):
            4.1.4.1. El sistema cambia el estado del perfil del colaborador a Inactivo, retira su agenda de la consulta de disponibilidad para clientes y revoca sus accesos de inicio de sesión al sistema
            4.1.4.2. El sistema envía la notificación de cambio de estado al correo del empleado
               end if
         end if

(REACTIVACIÓN DE UN EMPLEADO)
Steps
1. El Dueño de Establecimiento accede al filtro de "Empleados Inactivos" dentro de la gestión de personal.
2. Selecciona un profesional en estado Inactivo y presiona el botón "Reactivar / Habilitar Empleado".
3. El sistema evalúa las condiciones del plan de suscripción del negocio y la ficha del empleado:
    3.1. if la adición del colaborador excede el límite máximo de personal permitido por el plan de suscripción activo de la sede
        3.1.1. El sistema frena la reactivación y notifica "No es posible reactivar al colaborador. Se ha alcanzado el límite de personal permitido en tu plan actual. Actualiza tu suscripción para continuar".
    3.2. else if
        3.2.1. if el empleado no tiene ningún servicio asignado de la sede O sus horarios de trabajo están vacíos:
            3.2.1.1. El sistema notifica "El colaborador fue reactivado pero requiere asignación de servicios (RF31) y horarios para aparecer disponible a los clientes".
        3.2.2. else if El sistema cambia el estado del empleado a Activo, restablece sus permisos de acceso a la plataforma y publica su agenda en el motor de reservas de la sede.
            3.2.2.1. El sistema notifica la reactivación de la cuenta al colaborador (<<include>> RF14).
               end if
         end if
